# Клиент мониторинга аллергии

React + TypeScript + Vite, график на Recharts. Только публичный просмотр:
входа в систему, редактирования и удаления данных нет.

## Запуск

Нужен Node.js 20.19+ или 22.12+ и запущенный Django backend.
Из папки `frontend/`:

```bash
npm ci
npm run dev
```

Откройте адрес из вывода Vite (обычно http://localhost:5173).
Запросы `/api/` проксируются на `http://127.0.0.1:8000`.
Другой адрес бэкенда можно указать в `.env`:

```bash
cp .env.example .env
```

Измените `BACKEND_URL` и перезапустите Vite. Ключ эмулятора клиенту не нужен.

## Возможности

- Локации загружаются из `GET /api/v1/locations/`
- История загружается из `GET /api/v1/measurements/` с `location_id` и периодом
- Доступны индекс риска и все 16 исходных показателей API
- Периоды 1, 7, 30 календарных дней заканчиваются днём последнего наблюдения
  в выбранной локации, поэтому доступны и исторические данные
- Можно выбрать свои даты или всё время; даты включают целые дни
  в часовом поясе браузера и передаются серверу в UTC
- Сначала загружаются последние 500 записей, далее — кнопкой по 500
  до ограничения API по offset; при неполной истории показано уведомление
- У разных станций отдельные линии; отсутствующие значения не заменяются нулями
- Минимум и максимум относятся только к загруженным данным, последнее значение —
  к последнему измерению выбранного периода, даже если в нём показатель отсутствует
- Есть подсказки при наведении, таблица значений, состояния загрузки,
  пустых данных и ошибок с повторным запросом, кнопка ручного обновления
- График и фильтры адаптируются к узкому экрану

Данные обновляются вручную. При одновременном добавлении измерений offset-страницы
могут смещаться; повторно полученные записи удаляются по `id`, для свежего
снимка используйте «Обновить».

## Сборка и размещение

```bash
npm run build
```

Команда проверяет TypeScript и создаёт `dist/`. Тесты не запускаются.
Раздавайте `dist/` статическим сервером на том же origin, что и API,
либо настройте reverse proxy для `/api/` на Django. Прокси Vite работает
только в режиме разработки; `BACKEND_URL` не встраивается в браузерный код.

Пример конфигурации nginx (пути и upstream замените на свои):

```nginx
server {
    listen 80;
    server_name localhost;
    root /var/www/allergy-monitor/dist;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```
